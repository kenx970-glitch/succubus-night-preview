# SUCCUBUS NIGHT — 現在の構成

更新日：2026-10-10。ユーザーの最新指示を反映した、スマートフォン中心のローカルWeb版。

## サービスの流れ

1. アカウントにログインし、ルナ・ミオ・レイナから担当を選ぶ。
2. 入店映像から、選択したキャストと向かい合う席へ移る。
3. 購入済みSで自然な音声会話を行う。定型会話・主要な物語は無料。
4. 動画を任意に視聴して無料Gを獲得し、ドリンク・ギフトを贈る。
5. 会話・来店・イベント・ギフトでキャスト別の物語が進む。

## 通貨の役割

| 項目 | S | G |
| --- | --- | --- |
| 入手 | 日本円で購入する設計 | 動画視聴の報酬 |
| 使用 | 自然なAI音声会話 | キャストへのギフト |
| 現在の価格・報酬 | 1円=1S、返答1回5S | テスト動画30秒=100G |
| 相互交換 | なし | なし |
| 現金交換・送金 | なし | なし |

最新仕様では、すべてのギフトはGのみ。Sをギフトに使うリクエストはサーバーが拒否する。プレミアムボトルも18,000G。以前のG/S共通メニュー・S専用ボトル仕様は変更済み。

500Sなら料金5Sの返答を最大100回利用できる。残高不足時に自動購入しない。マイクを開始しただけではSを消費せず、発言を送信した時点で料金を予約する。

## 音声会話

2026-10-10にGemini Liveを標準として実装。Googleのキー設定待ち。Googleへの実接続・試聴・実速度測定は未実施。

```mermaid
sequenceDiagram
    participant P as プレイヤー
    participant B as ブラウザ
    participant A as 認証付きNode中継
    participant D as SQLite台帳
    participant G as Google Gemini Live
    P->>B: 年齢・料金・送信先を確認
    B->>A: ログイン + CSRFで接続券を取得
    B->>A: 一度だけ使える券でWebSocket接続
    A->>G: 成人キャスト設定・直近8発言・声を設定
    B->>A: 発話開始（価格・操作キー）
    A->>D: 残高確認・5Sを一度だけ予約
    A-->>B: 予約成功と残高
    B->>A: 16kHz PCMを順次送信
    A->>G: 予約済み発言のみ中継
    B->>A: 発話終了（無音800ms / 手動）
    G-->>A: 24kHz音声チャンクと文字起こし
    A-->>B: 音声を即時中継・表情の目安
    B-->>P: 音声を順次再生・担当の動画切替
    alt 返答が完成
        A->>D: 返答・24kHz WAV・使用量を保存
        A-->>B: 利用確定・保存済み音声URL
    else 未完了・切断・上限
        A->>D: 5Sを一度だけ返却
        A-->>B: 停止・残高・再開案内
    end
```

- 入力30秒、出力音声20秒。最大出力トークン1024、返答待ち30秒、無音45秒、接続4分、1接続8返答。
- 一度だけ使える30秒の接続券は利用者・担当に紐付く。Origin、セッション、CSRFを検証。GoogleのキーやGoogleへ直接接続できるトークンをクライアントへ渡さない。
- 全体同時2接続、開始済み発言は日本時間1日100回、利用者1日60回。失敗も上限に数える。金額の厳密な日予算制御ではない。
- 料金は返答1回5S。録音開始だけでは消費しない。発話開始時に予約し、未完了・切断・無音・不正形式は返却する。
- PCMはブラウザで44.1/48kHzから16kHzへ位置を保持して変換。短い前置き音声を残し、冒頭の欠落を減らす。返答中はマイク送信を休止。停止ボタン・非表示・離脱で接続と未完了の返答を停止。
- Luna/Aoede、Mio/Zephyr、Reina/Leda。可愛い成人女性のフランクな日本語を指示。実際の声の評価はキー接続後。
- 入力音声はDBに保存しない。文字起こし・返答・返答WAV・料金履歴・Googleの使用量報告・最初の音声までの時間を保存する。外部保持はGoogle側の方針に従う。
- 表情は返答文字のキーワードを目安に選ぶ。これは独立した感情認識モデルの判定ではない。動画は事前生成素材で完全なリップシンクではない。
- キャストの指示で安全方針を設定し、禁止された課金圧力などの文字起こしを検出した場合は停止する。ストリーミング音声は判定前に一部が再生され得る。商用化には入力/出力の評価・モデレーションの追加検証が必要。
- 聞き直しは追加消費なし。切断した発言を自動再送しない。1サーバー再起動時は未完了の予約を返却。複数サーバー化には分散制御が必要。
- 旧FalのWhisper→Gemini返答→安全判定→Gemini TTSは明示的な `VOICE_BACKEND=fal-gemini` の場合のみ。キー未設定で自動フォールバックしない。

旧方式は約36秒の実接続試験済み。Gemini Liveの速度として扱わない。[旧記録](VOICE-VERIFICATION.json)。Gemini LiveのローカルWebSocket代替試験で予約・複数音声チャンク・完了・再生・返却・上限・所有者分離を検証。

[設定手順](GEMINI-LIVE-SETUP.md)。

## キャストの映像

- 成人の架空キャスト3人。選択した1人のみが席に表示される。
- imagegenでキャスト別の席の画像・表情参照画像を生成。
- Fal Kling 3 Proで、各キャストに待機・通常会話・喜び・悲しみ・軽い怒り・驚きの6種、合計18本の5秒映像を実生成。
- 開始・終了の参照画像を共通化し、2つのプレイヤーを重ねて切り替える。黒いリセット画面を避ける。
- 最初の案内映像は一度だけ再生し、終わる直前に席の映像へ移る。
- 返答のemotionに合わせて動画を切り替え、音声終了後は待機へ戻る。
- 発音単位の完全なリップシンクではない。映像・音声の新規API生成は再生のたびには行わない。
- MP4はRange配信・長期キャッシュ・ストリーミング配信。必要な担当・表情の素材だけ読み込む。

## 動画視聴と広告収益

現在はローカルのテスト動画。30秒の視聴確認で100G、テストの1日上限1,000G。中止可能で、視聴ノルマはない。

サーバーは視聴ID・所有者・経過時間・間隔を空けた視聴確認・付与済み状態を管理する。早期申請、他人の視聴ID、二重受取を拒否する。これは広告会社の収益確認や不正視聴防止を保証する仕組みではない。

**広告会社は未接続で、現在の視聴から広告収益は発生しない。** Web向けの候補はGoogle Ad Managerの任意参加型リワード広告。正式なアカウント・広告枠・コンテンツ審査・同意管理が必要。単価、配信率、地域等により収益は変わる。収益額は未確定。

Google Ad ManagerのWeb版にはアプリ向けSSVがない。クライアントのrewardイベントだけを、署名付きの広告証明と扱わない。正式接続時はGの付与上限・不正対策・照合方式を決める。Sの購入やAPI会話の残高と広告報酬を混ぜない。

公式資料：[Webリワード広告](https://support.google.com/admanager/answer/9116812?hl=ja)、[GPTの実装例](https://developers.google.com/publisher-tag/samples/display-rewarded-ad?hl=ja)、[報酬型広告の規則](https://support.google.com/admanager/answer/7496282?hl=ja)。

旧仕分けミニゲームの経済コードとテストは後方検証用に残るが、現在の利用画面は動画視聴へ変更。正式提供前に旧エンドポイントの整理が必要。

## UI/UXの方針

- スマホの下部に「ラウンジ・Gを獲得・物語」を固定。残高は上部で確認。
- 主な操作は44px以上。フォームは16px、本文は15〜16px。
- キャスト選択は横並び、音声開始を主操作とする。無料会話・映像設定は折りたたむ。
